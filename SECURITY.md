# Security policy

This is a portfolio reference implementation, not a production security baseline.
See [security considerations](docs/security.md) and the [future roadmap](docs/production-roadmap.md).

Do not post credentials, state, kubeconfigs, private keys, cloud-init logs, or
unredacted infrastructure identifiers in issues, pull requests, or Actions logs.
For a sensitive report, use GitHub private vulnerability reporting if enabled.
Otherwise contact [Hassan Hussain](https://github.com/hassanathussain) to arrange
a private reporting channel; do not include exploit details or secrets in a public issue.
No response-time or supported-version guarantees are made.

If a credential is exposed, revoke or rotate it through an authorized operational
process. Deleting a file or adding an ignore rule does not remove prior exposure.
